# 專案工作流管理議題與工程規範

> 本文件梳理專案在協作、版本控制、資料庫管理與 AI 輔助開發過程中的核心治理規則。

---

## 📌 議題一：Git 分支與審查策略 (Branching & Review)

*   **雙分支安全防護架構**：
    *   **`main` 分支**：對應正式機 / 雲端測試機，始終保持「最穩定、已驗收」狀態。
    *   **`dev` / `feature-*` 分支**：本地端開發與除錯。
*   **人工審查原則 (Human-in-the-Loop)**：
    *   AI 助手修改之代碼僅留於本地暫存。
    *   所有 `git commit` 說明與 `git push` 必須由專案負責人手動審查（Code Review）後親自執行，避免未驗證腳本自動提交造成 Regression。

---

## 📌 議題二：UAT 測試與資料庫保護防線 (Database Protection)

*   **唯一真實來源 (Source of Truth)**：
    *   一旦進入測試或正式運作，雲端伺服器上的資料庫即為真實數據來源。
    *   **嚴格禁止**從本地用 `.dump` 任意覆蓋伺服器資料庫，防止業務數據遺失。
*   **Schema 遷移規範**：
    *   資料表結構異動一律使用 Migration 腳本（向後相容追加欄位方式）。
    *   結構變更前必須先行執行資料庫快照備份。

---

## 📌 議題三：知識庫雙向連結健康度維護

*   新增或重命名 Markdown 檔案時，需確保其對應到 [[_docs/context/00_長期記憶導覽索引|00_長期記憶導覽索引]] 中的 MOC 表格。
*   保持檔案開頭的 `Plan_`、`Walkthrough_`、`Research_` 前綴統一，讓知識檢索維持極高可讀性。
