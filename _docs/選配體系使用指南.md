## 🗂️ 四大選配模組總覽與啟用時機

### 📦 類別 A：【工程功能模板模組】（`_docs/_templates/optional/`）

| 模板檔案 | 啟用時機 | 核心功能 |
| :--- | :--- | :--- |
| **`tpl_Eng_Review.md`** | 開發敏感功能（登入/金流/Webhook/權限）或上正式機前夕。 | AI 扮演稽核員排查 Token 簽章、SQL 注入、5s Timeout、try-catch 降級與個資脫敏。 |
| **`tpl_Smoke_Test.md`** | 交付客戶/顧問 UAT 驗收前，或重大版本發布前。 | 定義 Happy Path、邊界與權限攔截清單，輔助 AI 撰寫自動化測試腳本。 |
| **`tpl_Project_Showcase.md`** | 專案順利上線結案，或工程師整理履歷作品集時。 | 由 AI 從知識庫自動撈取數據，萃取成具備架構圖、業務價值與 3~5x 提效數據的展示簡報。 |
| **`tpl_AI_Chat_Summary.md`** | 歷經 2 小時深度除錯（如 Docker port 衝突、字元集衝突、Race Condition）後。 | 濃縮為「現象 ➔ 失敗路徑 ➔ 根本原因 ➔ 解決代碼」的永久知識卡片。 |
| **`tpl_obs_temp_enhancement_proposal.md`** | 專案實戰落地淬煉出優良架構、新工具或新工作流時。 | 總結為母模板架構增強建議書 (RFC)，引導去業務化參數設計並啟動跨庫反哺。 |
| **`tpl_Meeting_Briefing.md`** | 與客戶 PM、外部 ERP 顧問或跨團隊召開規格對齊/進度會議前夕。 | 快速梳理已完成成果、劃定技術與責任邊界、整理待決策議題選擇題與共識清單。 |

---

### ⚡ 類別 B：【AI 開發工作流模組】（`_docs/workflows/`）

| 工作流檔案 | 啟用時機 | 核心功能 |
| :--- | :--- | :--- |
| **`wf_gstack_review.md`** | 全新專案啟動時，或面臨重大產品方向抉擇時。 | 調用 gstack `/office-hours` 挑戰產品偽需求與 `/plan-eng-review` 工程資安審查。 |
| **`wf_adversarial_code_review.md`** | 開發完成、準備執行 `git commit` 與 Push 之前。 | 叫 AI 切換為「嚴苛的資安架構師 / 滲透測試員」視角，極限挑刺本次 Git Diff。 |
| **`wf_tdd_testing.md`** | 核心業務邏輯開發（勞健保精算、工單狀態機、金流對帳）。 | 規範「先寫失敗的整合測試 (Red) ➔ 再寫代碼通過測試 (Green) ➔ 重構」的標準 SOP。 |

---

### 🏗️ 類別 C：【頂級架構範式模組】（`_docs/context/02_技術研究與分析/patterns/`）

| 範式檔案 | 啟用時機 | 核心功能 |
| :--- | :--- | :--- |
| **`pat_async_mq_upsert.md`** | 系統面臨高頻資料同步、大批次匯入或瞬間高並發時。 | 標準化「API 接收 ➔ RabbitMQ 佇列 ➔ Worker ➔ 原子 Upsert 寫入 DB ➔ 前端輪詢/SSE」架構。 |
| **`pat_strangler_migration.md`** | 跨大版本系統遷移（如 Odoo 14 ➔ 19）或舊 ERP 模組重構。 | 規範在舊系統邊緣建立防腐層 (Adapter)，以 Python ORM ETL 腳本達到新舊資料 0 元差額驗證。 |

---

### ⏳ 類別 D：【治理與追蹤模組】（`_docs/`）

| 治理檔案 | 啟用時機 | 核心功能 |
| :--- | :--- | :--- |
| **`_docs/技術債與延後決策.md`** | 為了快速推 MVP 而暫時妥協架構（如先用 Polling 替代 WebSocket）。 | 為妥協建立編號 `[TD-001]` 並標註「重構觸發條件」，防止技術債被遺忘。 |

## 💡 AI 常用調用 Prompt 指令庫

### 1. 調用【資安與工程審查】
> *「請參考 `_docs/_templates/optional/tpl_Eng_Review.md`，扮演嚴苛的資安架構師，針對我們即將動工的 [功能名稱] 進行全面資安與例外防禦盤點。」*

### 2. 調用【對抗式代碼審查】
> *「請依據 `_docs/workflows/wf_adversarial_code_review.md`，讀取本次 Git Diff，以滲透測試員視角挑出潛在的 SQL 注入、缺乏 Timeout、以及未捕獲 Exception 的代碼壞味道。」*

### 3. 調用【跨團隊會議發言要點準備】
> *「我們明天即將與客戶 PM 及 ERP 顧問召開規格對齊會議。請參考 `_docs/_templates/optional/tpl_Meeting_Briefing.md`，從我們近期的 Walkthrough 與待辦事項中，梳理出『已完成成果』、『責任邊界宣告』以及『待決策議題選項清單』，整理成一份精煉的會議發言要點草案。」*

### 4. 調用【專案成果展示萃取】
> *「專案已順利結案，請參考 `_docs/_templates/optional/tpl_Project_Showcase.md`，從本知識庫撈取數據，萃取成一份包含架構圖、核心亮點與 AI 提效數據的對外展示簡報。」*

### 5. 調用【深度排錯對話萃取】
> *「我們剛剛解決了這個棘手的問題，請參考 `_docs/_templates/optional/tpl_AI_Chat_Summary.md`，將剛才的排錯過程濃縮為一張避坑指南知識卡片。」*

## 🌐 附錄：v2.3.0 跨領域專屬模板庫導引 (商業管理與學術研究)

在 **v2.3.0** 中，母模板正式將知識管理維度從軟體工程擴充至「商業管理」與「學術論文研究」。

當您透過 `init-new-project.ps1` 建立專案時，若選擇非軟體模式（如 `-Mode Business` 或 `-Mode Research`）：
1. **專屬模板自動注入**：
   - 💼 **商業管理庫 (`_docs/_templates/business/` 共 7 份)**：精實畫布、OKR檢視、GTM策略、競品矩陣、行銷漏斗、商業實施計畫 (`tpl_Plan_Business`) 與結案復盤 (`tpl_Walkthrough_Business`)。
   - 🎓 **學術研究庫 (`_docs/_templates/research/` 共 5 份)**：研究提案 (`tpl_Research_Proposal`)、文獻評析 (`tpl_Literature_Review`)、實驗日誌 (`tpl_Experiment_Log`)、投稿檢核 (`tpl_Paper_Submission_Checklist`) 與假說總結 (`tpl_Research_Findings`)。
2. **軟體選配資產自動裁剪 (ADR-10)**：
   - 為了維持開箱極致純粹，本指南所介紹的軟體專屬模組（類別 B 工作流、類別 C 架構範式、技術債追蹤器、伺服器/容器模板）將在商業與研究模式下被自動裁剪。
   - 跨領域通用的「會議發言簡報 (`tpl_Meeting_Briefing`)」、「成果展示 (`tpl_Project_Showcase`)」、「深度排錯避坑卡 (`tpl_AI_Chat_Summary`)」與「架構反哺建議書 (`tpl_obs_temp_enhancement_proposal`)」則依然獲得完整保留。
