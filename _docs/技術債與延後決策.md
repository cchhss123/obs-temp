# ⏳ 技術債與架構延後決策追蹤器 (Technical Debt & Deferred Decisions)

> 本文件記錄專案在快速推進 MVP 或階段性交付時，為了時程而暫時妥協的「架構技術債」與「延後決策 (TODOS)」。
> **目的**：讓妥協透明化，並設定「重構觸發條件」，防止技術債演變為無法維護的黑洞。

---

## 📌 技術債管理原則

1. **唯一編號**：每個技術債均賦予 `[TD-001]` 唯一識別碼。
2. **標註代價與風險**：明確記錄「為什麼現在妥協？」以及「未來不修會有什麼風險？」。
3. **設定觸發重構條件 (Refactoring Triggers)**：達到具體業務指標（如用戶數、資料量、QPS）時強制啟動重構。

---

## 📋 進行中技術債清單 (Active Debt)

### 📌 [TD-001]：【例如：暫以 Polling 輪詢替代 WebSocket 即時推播】
*   **妥協背景**：為了在 3 天內交付 MVP，暫不配置 WebSocket / SSE 伺服器與 Redis Pub/Sub。
*   **潛在風險**：當同時在線人數超過 500 人時，頻繁 AJAX Polling 會增加資料庫負載。
*   **暫定緩解措施**：前端加入 `document.visibilitychange` 判斷（分頁切換時暫停輪詢），並設定 5 秒間隔。
*   **觸發重構條件**：👉 **【當系統同時在線用戶 > 300 人，或伺服器 CPU > 60% 時】**。
*   **預計重構方案**：改用 Cloudflare WebSockets 或 Redis Pub/Sub + SSE。

---

### 📌 [TD-002]：【例如：管理員權限撤銷即時性 (T002)】
*   **妥協背景**：登入驗證目前依賴 Session 快取，管理員在後台被停權時，需等待 Session 過期（或下次登入）才生效。
*   **潛在風險**：被停權的管理員在 Session 有效期內仍可操作後台。
*   **觸發重構條件**：👉 **【第一階段 UAT 測試結束，進入 Phase 2 權限管理時必須修復】**。
*   **預計重構方案**：在 `auth_check.php` 中每次請求即時比對資料庫 `is_banned` 與 `is_admin` 狀態。
